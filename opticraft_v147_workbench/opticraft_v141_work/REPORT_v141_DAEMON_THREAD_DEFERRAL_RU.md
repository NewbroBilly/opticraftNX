# OptiCraft Switch v141 — устранение блокировки запуска daemon-потоком

## Причина

Реальный пробник оригинального `minecraft.jar` останавливался внутри `hj.run()V`, `pc=16`. Проверка bytecode через `javap` показала, что `hj` наследует `Thread`, является daemon-потоком и выполняет цикл `Minecraft.L` + `Thread.sleep(2147483647)`.

В `ObjectBytecodeInterpreter` вызов `Thread.start()` ранее исполнял `run()` синхронно в том же стеке. Это неверная семантика Java Thread и блокировало основной поток ещё до продолжения инициализации окна.

## Исправление

Daemon-потоки теперь не исполняются inline. Они получают `thread_started=1`, `thread_alive=0`, `thread_deferred=1` и оставляются для будущего cooperative scheduler. Не-daemon поток Minecraft продолжает исполняться прежним способом, чтобы добраться до запуска игрового цикла.

## Ограничение

Полноценный многопоточный Java scheduler ещё не реализован. В этой версии фоновые daemon workers только откладываются, а не исполняются параллельно. Это целевое промежуточное поведение для прохождения стартовой инициализации, а не полная реализация `java.lang.Thread`.
